# 3JSE Website

## What this is

**3jse.com is the official website of the 3JSE project.** The domain is owned by the project, the site is live, and — like everything else in this repository — it is part of the project and kept updated alongside the engine. It is not an external marketing artifact; it ships with the repo.

The site has two jobs:

1. **Promotional landing page** (`site/index.html`) — the public pitch, in the editor's own visual identity: a live Three.js hero inside a framed "Viewport" panel, the comparison table, the four frontends, the ten-layer architecture, the panel inventory, and the roadmap.
2. **The design manual** (`site/manual.html`) — all of `docs/`, baked into a single cross-linked page, generated from the markdown so it can never drift from the source of truth.

## Where it lives

Everything is under `site/` in this repository, alongside the engine code:

| Path | What it is | Edit it? |
|---|---|---|
| `site/index.html` | Promotional landing page | Yes — directly |
| `site/manual.html` | Generated design manual | **No** — generated by the script below |
| `site/build-manual.mjs` | The doc-to-manual baker | Yes |
| `site/assets/css/site.css` | Shared stylesheet (landing + manual) | Yes |
| `site/assets/js/main.js` | Three.js hero scene (bloom, particles, parallax) | Yes |
| `site/assets/img/` | Logo, banner, architecture SVGs | Yes |
| `site/README-DEPLOY.md` | Deployment and maintenance runbook | Yes |

## Keeping it updated — the policy

The website is updated by the same PR process as the engine. Concretely:

- **Docs changes update the manual automatically in practice:** after editing anything under `docs/`, run `node site/build-manual.mjs` and commit the regenerated `site/manual.html` in the same change. The build script is a plain Node script with no dependencies.
- **Positioning changes update the landing page in the same PR.** The comparison table, the roadmap phases, the panel inventory, and the pitch copy on `index.html` mirror `README.md` and the relevant docs — when one changes, the other changes with it, in the same commit. A PR that updates `docs/VISION.md` without checking `site/index.html` is incomplete.
- **Design changes inherit from the editor.** The site's palette tokens are the editor's own (`#0c0d11` background, `#15171d` surface, `#262b36` borders, cyan/violet/magenta brand gradient — see `apps/editor/src/App.css`), and the visual language is the editor's panel/dock chrome. If the editor's identity evolves, the site evolves with it.
- **The manual is a snapshot, not a separate docs host.** There is no second editing surface — `manual.html` is always regenerated from `docs/`. If the manual on the site is stale, the fix is running the script and committing, not editing HTML by hand.

## Deployment

Static files, no build step, no server code. Upload the **contents** of `site/` (index.html, manual.html, assets/) to the web root of the 3jse.com host over SFTP — the full runbook, including the self-hosting option for the Three.js CDN dependency, is in `site/README-DEPLOY.md`. The site's Three.js hero loads `three@0.170.0` from jsdelivr; it degrades to the static SVG banner when WebGL or the CDN is unavailable.

## Posture

The site is promotional in tone, but it is honest by policy — the same policy as `VISION.md`: the comparison table concedes the rendering ceiling, the roadmap states the pre-alpha status plainly, and every claim traces to a doc in the manual. The website is the storefront, not a second source of truth.
